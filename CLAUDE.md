# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Статический сайт-зеркало таблицы **юношеских** рекордов России по плаванию с russwimming.ru (`/records/junior/`). Сестринский репозиторий `russwimming-records` (взрослые рекорды) — тот же код: изменения переносятся копированием `scripts/`, `static/`, `tests/`, отличия только в брендинге (`SITE_*`, `DATA`, `ICON_LETTER`, счётчик Метрики, `DEFAULT_REPO_URL`, пункт FAQ про другое зеркало, подпись вордмарка в `gen_screens.py`). Данные скрейпятся раз в сутки GitHub Actions, сайт пересобирается и коммитится в `main`; хостит его Timeweb Apps (static-nobuild, `index_dir=/public`), который выкладывает закоммиченный `public/` по каждому push (домен `russwimming-records-junior.borozdov.ru`, A-запись на IP приложения). Интерфейс и тексты — на русском.

## Команды

```bash
pip install -r requirements.txt
```

```bash
python scripts/fetch.py && python scripts/build.py && python -m unittest discover -s tests
```

`fetch.py` ходит в сеть и **перезаписывает `data/junior.json` только при реальных изменениях**. `build.py` сети не требует, поэтому при правках вёрстки, стилей или скриптов достаточно его одного.

```bash
python -m unittest discover -s tests
```

Локальный просмотр (порт 4173, конфиг в `.claude/launch.json` — используй preview-инструменты, не Bash):

```bash
python3 -m http.server 4173 --directory public
```

Разовые скрипты, не участвующие в ежедневной сборке: `scripts/fetch_fonts.py` (обновить локальные шрифты в `static/fonts/` и `scripts/og-fonts/`; `--og-only` — только ttf для Pillow: их читают `gen_og.py`, `gen_icons.py` и `gen_screens.py`).

## Архитектура

Однонаправленный конвейер: **HTML источника → `data/junior.json` → `public/`**.

1. **`scripts/fetch.py`** — парсит `table.table-rating` на странице источника. Ожидает ровно 5 таблиц в порядке `CATEGORIES` (жен. 50м, жен. 25м, муж. 50м, муж. 25м, смешанные эстафеты) и **падает с RuntimeError**, если таблиц не 5, категория пуста или число рекордов упало больше чем на 10% относительно прошлого прогона (`check_sanity`). Это намеренно: молчаливая деградация хуже упавшего workflow. Нормализует дисциплину (`parse_discipline`: эстафета/дистанция/стиль, кириллическая «х» в «4 х 100 м»), состав эстафеты, результат в секунды, дату в ISO. Сортирует детерминированно.

2. **`data/junior.json`** — канонические данные в репозитории. `fetched_at` = момент, когда эти данные были сняты, а не когда последний раз опрашивали источник: файл не переписывается, если `categories` не изменились. История файла = история рекордов.

3. **`scripts/build.py`** — генерирует `public/`: главную, 5 страниц категорий (`/women-lcm/` и т.д.), `sitemap.xml`, `robots.txt`, `404.html` (на Timeweb не обслуживается: Caddy отдаёт на любой неизвестный путь `index.html` с 200, файл остаётся для других хостов), `offline.html`, `site.webmanifest`, `sw.js`, выгрузки `records.{json,csv,xlsx,md,txt}`, OG-картинку через `gen_og.py`, набор иконок и стартовых экранов iOS через `gen_icons.py`, скриншоты манифеста через `gen_screens.py`. Копирует `static/` в `public/assets/` (кроме `fonts.css` — он инлайнится в `<head>`). Ссылки на `style.css`, `app.js` и шрифты несут `?v=<хеш содержимого>` (`asset_url()`): версия нужна не HTTP-кэшу, а service worker'у — см. раздел PWA. Плюс `README.md` в корне репозитория — его собирает `gen_readme.py` из тех же данных, поэтому числа в описании репозитория нельзя править руками: они перезапишутся на следующей сборке (workflow коммитит README вместе с `data/` и `public/`). Соответствие закреплено `tests/test_readme.py`. Список форматов живёт в одном месте — `DOWNLOAD_FORMATS`, из него собираются и меню в шапке, и ссылки в футере.

4. **`static/app.js`** — прогрессивное улучшение поверх серверного рендера.

### Данные живут в DOM, а не в JSON

Ключевое решение всего фронта: **`app.js` не собирает строки таблицы**. `build.py` отдаёт готовую разметку с `data-`атрибутами (`data-sex`, `data-pool`, `data-stroke`, `data-relay`, `data-date`), а JS только:

- прячет строки классом `.is-hidden` и пустые категории — `.is-empty` на `<tbody>`;
- переставляет строки внутри их `<tbody>` при сортировке;
- строит чипы фильтров и подсвечивает выбранные.

Отсюда следуют правила, которые легко нарушить:

- **Никакого `innerHTML` по таблице.** Узлы живут от загрузки до выгрузки — поэтому фокус переживает клик по фильтру, а фильтрация стоит один проход по строкам.
- **Строка для поиска собирается в JS из конкретных ячеек** (`.disc-name`, фамилия, `.roster`, `.col-location`, `.result-value`, дата) плюс `aria-label` своего `<tbody>`, а не из `textContent` строки: в строку легко добавить служебную подпись, и она молча попадёт в поисковый стог.
- Контракт разметки с `app.js` закреплён тестами в `tests/test_markup.py` — переименование класса или `data-`атрибута ломает фильтры молча, без ошибок в консоли.
- Сортировка всегда идёт **внутри категорий**; группировка не выключается. Сортируются все пять колонок, заголовок — кнопка с тактами ↑ → ↓ → выкл. Индикаторы `aria-sort` обновляются при каждом `apply()`, а не только при смене порядка: иначе на свежей странице они остаются серверными `none` и расходятся с фактическим порядком строк.

### Иконки и фавикон

Константа вне зеркала — не следует лику сайта: **любая иконка бренда — чёрная литера
`#0d0d0d` на белом `#ffffff`**. Инверсии в наборе нет ни в фавиконе, ни в
apple-touch, ни в PWA-иконках, ни в сплэшах: раньше фавикон был титановым, а иконки
приложений обсидиановыми, и набор читался как два разных бренда — одно на вкладке,
другое на домашнем экране. Спецификация общая на все шесть сайтов, она в `BRAND.md`,
раздел «Иконки»; здесь она реализована на Pillow, потому что репозиторий
пересобирается на CI и обязан быть самодостаточным.

Фавикона в SVG у сайта нет: `<link>` несёт `favicon-120.png` (его же берёт Яндекс
в карточку поиска) и `favicon.ico` с 16/32/48 — для тех, кто молча дёргает
`/favicon.ico`, не заглядывая в `<link>`. `apple-touch-icon.png` 180,
`icon-{192,512}.png` и `icon-maskable-512.png` рисует `gen_icons.py` тем же локальным
Inter Bold, что и OG-картинку (`scripts/og-fonts/`): на раннере CI системного Inter нет.

Рост литеры и её центр — единственное, что здесь легко сломать, и ломается это молча:

- **Кегль не задаётся, а подбирается** (`letter_mask`). Рост литеры — доля высоты
  фактической краски от канвы, а не доля font-size: у «Р» и «Ю» при одном кегле разная
  высота очка, и сайты бренда на соседних вкладках выглядели бы разного размера.
- **`textbbox` не годится**: он меряет по ширине с апрошами, а правый апрош у «Р»
  больше левого — литера уезжала бы вправо примерно на 1% канвы. Литера рисуется на
  отдельном слое, и рост с центром берутся из его `getbbox()` — фактических границ
  краски. Метрики шрифта по той же причине не годятся по вертикали: ascender/descender
  считают выносные элементы, которых в прописной литере нет.
- **Мелкая иконка рисуется крупно и жмётся** (`_supersample`): 16px, нарисованный
  сразу в 16px, растеризатор гасит в полтона. `.ico` собирается вручную по той же
  причине — Pillow масштабировал бы 48px-исходник во все размеры и мылил 16px.

Отклонения проверяются числами в `tests/test_icons.py` (допуск — пиксель канвы),
там же — safe zone для maskable, равенство роста литеры между ролями и совпадение
манифеста со списком отрендеренных файлов.

Иконки приложений — `RGB` без альфа-канала и **без нарисованного скругления**: маску
кладут сами iOS и Android, а по альфе iOS антиалиасит край и даёт белую кайму даже
на полностью непрозрачной картинке.

Единственное исключение по размеру — maskable: система кропит его до центрального
круга ⌀80%, и литера там мельче (0.38 против 0.62).

### Производные поля

`build.py:enrich()` дописывает к каждому рекорду поля с подчёркиванием: `_pool` (из `is_25m_pool`, а не из категории — в смешанных эстафетах соседствуют обе воды), `_title` (дисциплина без дублирующей пометки «(бассейн 25 м)»), `_fresh` (считается от даты сборки, а не в браузере). `public_json()` вырезает их из публичной выгрузки — `records.json` остаётся чистым API.

`_fresh` держит трёх потребителей: бейдж «Новое», статистику «Обновлено за 12 месяцев» и описания страниц категорий — при правках `enrich` это легко не заметить.

### Одна разметка на все ширины

Мобильной версии как отдельной ветки нет: ниже 720px CSS превращает `tr` в grid, а подписи колонок приезжают из `data-label` на ячейках «Место» и «Дата». Поэтому на таблице проставлены явные `role="table|rowgroup|row|columnheader|cell"` — смена `display` стирает табличную семантику.

Липкие заголовки категорий сделаны по-разному не от лени: в настоящей таблице липким может быть только `td`, а когда `tr` становится grid-блоком — липким обязан быть сам `tr`, иначе «прилипать» ячейке некуда в пределах собственной строки.

Ниже 720px `thead` не прячется, а превращается в горизонтальный ряд кнопок сортировки: это единственный вход в сортировку на телефоне.

Мобильные решения, которые легко откатить, не заметив:

- **`:hover` живёт только внутри `@media (hover: hover)`** — на тач-экране он залипает после тапа, и тапнутый чип выглядит полувключённым. Отклик нажатия даёт `:active`. Новое ховер-правило вне такого блока — регресс на телефоне.
- **Тач-цели — блок `@media screen and (pointer: coarse)` в конце файла**, после мобильного блока: он поднимает `--chip-h` до 36px и высоту кнопок до 44; переставь его выше — и `.th-btn { height }` из мобильного блока его перебьёт. Высота чипа зафиксирована `line-height: 16px`, а не шрифтом: иначе резерв `.filters { min-height: var(--chip-h) }` под приезжающие из JS чипы врал бы при подмене Arial → Inter.
- **Поля ввода на тач-устройствах — 16px** (`#search`, `#ex-title`, блок `pointer: coarse` — iPad шире 720px тоже): ниже Safari зумит страницу при фокусе, и зум остаётся после. Enter в поле только прячет клавиатуру (`blur`), фильтр и так применяется по `input`.
- Лента фильтров идёт на полный вылет к кромке экрана (`margin: 0 calc(-1 * var(--pad-*))`): последний чип режется физическим краем — это и есть подсказка прокрутки, маски-градиенты брендбук запрещает. Чипы «Все» на телефоне скрыты CSS (`.chip[data-value="all"]`): повторный тап по активному чипу снимает выбор, а четыре «Все» — половина ширины ленты. В JS они остаются — десктоп их показывает.
- Статистика в герое на телефоне — строки «цифра слева, подпись справа» через hairline (рецепт брендбука), навигация — сетка 2×3. В ландшафте ниже 500px высоты **ничего не липнет** (`max-height` медиазапрос) — липкий стек съедал бы две трети экрана.
- Меню «Скачать» ниже 720px — нижний лист: скрим — псевдоэлемент `.dl.open::before` с `position: fixed`, он считается от viewport только пока у `.site-header` нет `transform`/`filter`/`backdrop-filter`. Тап по скриму отдаёт `e.target === .dl` — так его и ловит `app.js`. Пока лист или окно экспорта открыты, страница заперта `lockScroll()`: на coarse-указателе `body` получает `position: fixed` (единственное, что держит тач-скролл в iOS), `top` компенсирует прыжок.
- Кнопка «Наверх» на тач-экране показывается только при прокрутке **вверх**: fixed справа внизу она накрывает результат и дату последней видимой карточки. Её `z-index: 35` — ниже шапки (40), чтобы скрим нижнего листа (живёт в стек-контексте шапки) накрывал и её.
- Класс `keyboard-open` на `<html>` ставит `app.js` по `visualViewport` (порог 140px), а не по фокусу: на десктопе клавиатуры нет, и реакция на `focusin` заставляла бы вёрстку прыгать. С классом липкая панель схлопывается до одного поля поиска.
- Всё прибитое к краям экрана отступает на `env(safe-area-inset-*)` через `--safe-t/--safe-b/--pad-l/--pad-r`; `--header-stick` включает верхний инсет, поэтому липкие смещения ничего не знают про вырез. Работает только при `viewport-fit=cover` в мета-viewport.

Скругление таблицы держится на `overflow: clip` у `.table-frame`. `hidden` здесь нельзя — он создаёт скролл-контейнер и убивает липкий `thead`; скруглять сами ячейки тоже нельзя — селектор `tr:first-child td:first-child` попадает в первую строку **каждой** группы и срезает ей угол.

### Шаблон страницы

Весь HTML — в `PAGE_TEMPLATE` (`.format()`). **В шаблоне нет ни одной литеральной фигурной скобки**: инлайновые скрипты (`THEME_SCRIPT`, `METRIKA`) и JSON-LD приходят готовыми строками через плейсхолдеры. Не вставляй в шаблон JS или CSS напрямую — либо выноси в константу, либо удваивай скобки.

Ответы в `FAQ_ITEMS` — **HTML, а не текст**: внутри живут ссылки. `faq_section()` их не эскейпит (это константа, не пользовательский ввод), а `jsonld_graph()` снимает теги через `faq_plain()`. Второго «чистого» поля рядом с ответом нет намеренно: видимый текст и `FAQPage` обязаны совпадать, а два поля разъезжаются молча. Вернуть `html.escape` на ответ — значит показать людям `<a href=…>` текстом. Вопрос эскейпится как и раньше.

Исходящие ссылки бренда собирает `brand_link()` — с UTM, чтобы на borozdov.ru было видно, откуда пришли. Точек три: кнопка в полосе автора под шапкой (`header_by`), кнопка в подвале (`footer_by`) и ссылка в ответе про автора. Полоса автора — тот же блок `подпись + кнопка`, что в подвале: подпись приходит из константы `SIGNATURE` в оба места, тест сверяет, что они совпадают. Полоса стоит в потоке и **не липкая** намеренно — липкий стек на телефоне и так съедает пятую часть экрана; в самой шапке ссылки на бренд нет. В `publisher.url` JSON-LD меток быть не должно — структурированные данные несут чистый URL.

Интерактивные контролы помечены классом `js-only` и скрыты, пока инлайновый скрипт не снимет `no-js` с `<html>`: без JS не должно оставаться поиска и кнопок, которые ничего не делают. Ссылки на категории и выгрузки — настоящие `<a href>` и работают всегда.

### Стиль

`static/style.css` реализует брендбук BOROZDOV: два лика — ОБСИДИАН (тёмный) и ТИТАН (светлый), `data-theme` на `<html>`, при первом визите берётся системная тема, дальше только ручной выбор. Правила, которые важно не откатить:

- Цвета — только через роли-переменные. `--hairline` для декоративных границ, `--strong` для границ интерактивных элементов, `--slate` для вторичного текста. Роли «третичный текст» нет: она давала контраст ниже 4.5.
- Липкие смещения считаются от `--header-stick` (61px = шапка + её граница) и `--thead-h`; высоту липкой панели контролов CSS знать не может — её меряет `ResizeObserver` в `app.js` и пишет в `--controls-h`.
- **Все раскладочные медиазапросы помечены `@media screen and (...)`.** Печатная полоса A4 за вычетом полей — примерно 703px, то есть *меньше* мобильного порога 720px: без `screen` на бумагу уезжала мобильная вёрстка (карточки вместо таблицы, ряд кнопок вместо шапки, подписи «Дата:»).
- В печати `body` возвращается в `display: block`: флекс-контейнер ломает разбиение на страницы в Chrome. Каждая категория начинается с новой страницы (`tbody + tbody { break-before: page }`) — повторить заголовок группы средствами CSS нельзя, повторяется только `thead`.
- `tbody.is-empty` скрывается через `!important`: иначе мобильное `table.records tbody { display: block }` перебивает его по специфичности, и отфильтрованная категория печатает свой заголовок на отдельной пустой странице.
- `--zebra` в CSS не используется — его читает `app.js` для канвы экспорта.

### Экспорт PNG/PDF

Пункты PNG и PDF в меню скачивания открывают окно экспорта (`export_dialog()` в `build.py`, логика в `app.js`) с настройками и живым предпросмотром. Настройки лежат в localStorage `rus-records-export-v1`.

Лист рисуется на canvas **в условных единицах: ширина листа всегда 1000**, а `scale` подбирается под целевой размер. Поэтому одна и та же вёрстка годится и для превью 620px, и для 300 dpi. Содержимое канва читает из DOM теми же хелперами, что и поиск (`text()`, `athleteName()`): заголовок из `h1`, эйрбрау из `.hero .label`, статистику из `.stat-strip`, состав из `.roster`, свежесть из `.badge-fresh`. Захардкоженных строк в листе нет — на странице категории он называется её именем.

**Настраивается только то, что меняет смысл листа:** лик, форма (страница или лента), заголовок и три переключателя содержимого. Остальное зафиксировано намеренно:

- ширина картинки `IMG_W = 2480` (300 dpi на A4, 8.7 Мпикс);
- PDF всегда A4 — у всей A-серии пропорция одна (√2), поэтому выбор «A4 или A3» менял бы только бумагу, а не вид;
- размер текста один (`TEXT_SCALE = 1`);
- фильтры и поисковый запрос на лист не выносятся вовсе: человек пишет в поиск что угодно, и на плакате это выглядит случайной надписью.

В меню скачивания PNG и PDF стоят первыми и отделены `.dl-sep` от готовых выгрузок: сверху то, что собирается на клиенте с учётом фильтров, снизу — файлы данных.

Что легко сломать:

- масштаб упирается в потолок площади ~16 Мпикс — **iOS выше него отдаёт пустую картинку, причём `toBlob` успешно резолвится**; отсюда максимальная ширина 3300;
- если содержимое короче листа, строки растягиваются (`stretch`, не больше 1.55): наполовину пустой A4 читается как ошибка вёрстки. Когда записей совсем мало, растяжки не хватает и подпись предлагает «Ленту»;
- трекинг у прописных рисуется посимвольно (`tracked`) — `ctx.letterSpacing` поддержан не везде;
- подзаголовок с фильтрами и поисковым запросом по умолчанию **выключен**: в поиск человек пишет что угодно, и на плакате это выглядит случайной надписью.

QR, домен и `BY BOROZDOV` рисуются всегда и переключателя не имеют — это выходные данные листа. QR ведёт **не на домен, а на переходник `/go/`** (константа `QR_TARGET` в `build.py`): цель можно поменять, не перевыпуская уже напечатанные плакаты. Переходник помечен `noindex` и в sitemap не попадает. Матрицу считает `static/vendor/qrcode.js`, рисуется тёмными модулями на светлой плашке в любом лике — инвертированные коды читают не все сканеры. jsPDF и qrcode.js лежат локально и грузятся лениво.

Кнопки «Печать» в шапке нет — печать живёт через Cmd+P, `setPrintMeta` висит на `beforeprint`.

Окно экспорта на телефоне: превью первым (`order: -1`), настройки под ним, кнопки прибиты к низу над safe-area; DOM-порядок не меняется, поэтому первый фокус остаётся на крестике. Пока окно открыто, остальные дети `body` (кроме тоста — в нём может быть «Обновить») получают `inert`, а в историю кладётся запись: системная «Назад» на Android закрывает окно, а не приложение (`popstate` → `closeExport(true)`, свой `closeExport()` делает `history.back()`). Превью рисуется шириной `620 × devicePixelRatio` (до 1240), иначе на телефоне лист размыт.

### PWA: манифест, service worker, офлайн

Сайт устанавливается как приложение. Что здесь держится на неочевидных решениях:

- **Service worker генерирует `build.py`** (`SW_TEMPLATE` → `public/sw.js`, подстановка через `replace`, не `format`: JS состоит из фигурных скобок). Пишется **последним шагом `main()`**: имена кэшей — `sha256` по байтам уже записанных файлов (`content_hash`). Два кэша: `app-<хеш>` (страницы, `offline.html`, css, js, манифест) меняется вместе с данными, `static-<хеш>` (шрифты, при первом обращении — vendor) — годами тот же. **Никаких timestamp в версии**: иначе `sw.js` менял бы байты на каждом прогоне, и CI коммитил бы `public/` ежедневно. Нет файла из прекэш-списка — сборка падает (`FileNotFoundError`), как `check_sanity` в `fetch.py`: молча неполный прекэш роняет `addAll` у всех пользователей без единой ошибки на странице.
- **URL ассетов версионированы хешем содержимого** (`asset_url()`), и тот же URL идёт в прекэш. Это гарантия, что HTML и `app.js` всегда из одной сборки: старый кэш новые URL не найдёт и уйдёт в сеть. Контракт закреплён в `tests/test_sw.py::test_html_references_same_urls`.
- Стратегии: выгрузки `records.*` — **первой веткой**: сеть без таймаута, при обрыве последняя копия из static-кэша (в Chrome клик по `<a download>` приходит как navigate — иначе офлайн-страница уезжала бы в файл; а поиск по кэшам раньше сети сделал бы их cache-first навсегда). Навигации — сеть с таймаутом 3 с, при обрыве — прекэш этой сборки, иначе `offline.html`; сетевой HTML в кэш **не** кладётся, в `app-<хеш>` лежит ровно одна сборка. Ассеты — из именованных кэшей (глобальный поиск по всем кэшам запрещён: между install и activate он отдал бы файлы новой версии к старому HTML). Прекэш идёт с `cache: "reload"` — хостинг не шлёт `Cache-Control`, браузер кэширует эвристически по `Last-Modified`, и без этого в новый кэш попал бы вчерашний css из HTTP-кэша. Чужие origin'ы (Метрика, borozdov.ru) не перехватываются.
- Обновление — через тост «Таблица обновилась» с кнопкой «Обновить» (`SKIP_WAITING` → `controllerchange` → один `reload`). `controllerchange` приходит и при самой первой установке из-за `clients.claim()` — перезагрузка только по явному клику. Установленное приложение неделями живёт без навигаций, поэтому `reg.update()` дёргается при возвращении на экран, не чаще раза в час.
- `offline.html` — один самодостаточный файл без внешних ресурсов (тест это проверяет), в том же лике, что сайт: `THEME_SCRIPT` подставляется в него как есть.
- **iOS**: `apple-mobile-web-app-status-bar-style` = `default`, цвет статус-бара — из `meta[name=theme-color]` (по `id`), который переключает `applyLik`. `black-translucent` брать нельзя: он игнорирует theme-color, и в титановом лике часы пропадают на светлом фоне. Стартовые экраны — только `apple-touch-startup-image` (iOS не строит их из манифеста) и **только при `apple-mobile-web-app-capable`**; держим и его, и стандартный `mobile-web-app-capable`. Набор — константа вне зеркала: сплошное белое поле с чёрной литерой, без `prefers-color-scheme` (лик ручной и до загрузки страницы неизвестен). `gen_icons.SPLASH_SIZES` — единственный источник и файлов в `public/splash/`, и `<link>`-тегов (`startup_images()`); тест сверяет одно с другим. iPhone — портрет, iPad — обе ориентации.
- Манифест: `start_url` и `shortcuts` несут UTM того же словаря, что `brand_link()` (`utm_source=pwa`, `utm_medium=homescreen|shortcut`) — `readUrl()`/`persist()` в `app.js` трогают только свои ключи (`OWN_KEYS`), чужие остаются в адресе: Метрика стартует по `load` и должна увидеть метку в `location.href`. `app-<хеш>` зависит от HTML целиком, поэтому в разметке не должно быть ничего от окружения сборки: адрес репозитория берётся из `repo_url()` (env `REPO_URL` или адрес по умолчанию из `gen_readme`), а не пустая строка без переменной. `screenshots` (narrow/wide) для Richer Install UI Chrome рисует `gen_screens.py` на Pillow из тех же данных: настоящий снимок браузера на раннере CI невозможен и плавал бы байтами. Скриншоты — всегда обсидиан: это снимки самого сайта, а не иконка. OG-картинка, наоборот, идёт за иконками и рисуется в титане. `share_target` и `prefer_related_applications` не заводить, `orientation: any` не трогать (таблица на iPad в ландшафте шире).
- Точка входа в установку — пункт «APP» в меню «Скачать»: на Chromium появляется после `beforeinstallprompt`, на iOS показывается сразу и даёт тост с подсказкой «Поделиться → На экран Домой», в standalone скрыт. Офлайн обозначает полоса `#net-note` под шапкой (дата берётся из статистики через `text()`, не хардкодится) и тост.

## CI/CD

`.github/workflows/update.yml`: cron в 06:00 UTC + на каждый push в `main` + вручную. Тесты → fetch → build → коммит, **только если `git diff --cached` непустой**. Отдельного шага деплоя нет: коммит `public/` в `main` и есть деплой — Timeweb Apps (framework `static-nobuild`, `index_dir=/public`, автодеплой по вебхуку) выкладывает его на каждый push, включая бот-коммит. Поэтому `concurrency.cancel-in-progress: false`: прерванный посреди `git push` прогон — сорванный деплой. Сборка гоняется всегда: данные могли не измениться, но код — мог. Переменная `REPO_URL` добавляет в футер ссылку на историю изменений. Домен привязан A-записью на IP приложения (DNS `borozdov.ru` живёт на Timeweb); CNAME на технический домен `*.twc1.net` TLS не получает. GitHub Pages больше не используется, `public/CNAME` удалён.

Сборка детерминирована: у xlsx проставляются фиксированные `wb.properties`, иначе openpyxl пишет текущее время в `docProps/core.xml` и файл меняет байты на каждом прогоне (zip-заголовки внутри xlsx openpyxl всё равно штампует текущим временем — это известное исключение, остальные файлы побайтно стабильны, `sw.js` и картинки включительно). Проверка: две сборки подряд и сравнение хешей `public/` без `records.xlsx`.
